# ADR-003: Отдельный ключ для аудита

## Статус
Принято

## Контекст
Ключ шифрования vault (PBKDF2) используется для AES-GCM. Ключ подписи аудита имеет другую криптографическую роль.

## Решение
Выводить ключ подписи через **HKDF-SHA256** с info=`audit-signing` из master-derived material, **не** использовать encryption key напрямую.

## Обоснование
- **Разделение обязанностей (key separation):** компрометация ключа шифрования не даёт права подписывать прошлые логи как валидные (при forward-security политике).
- **Разные алгоритмы:** AES-256 требует 32 байта симметричного ключа; Ed25519 — 32 байта seed с иной семантикой.
- **Кэширование:** audit seed хранится в `KeyCache` отдельно от encryption key и обнуляется при logout.

## Последствия
- `KeyManager.get_audit_signing_seed(password)` вызывается при успешном login.
- Seed никогда не записывается на диск.
