# ADR-004: Обработка конфиденциальных данных в логах

## Статус
Принято

## Контекст
Журнал аудита читается администратором и экспортируется; утечка паролей через логи недопустима.

## Решение
`AuditLogger._sanitize_details()` рекурсивно заменяет значения полей с ключами из `SENSITIVE_KEYS` на `"[REDACTED]"` и фильтрует строки с паттернами `password=`, `secret=`.

## Обоснование
- Whitelist безопасных полей хрупок при расширении событий.
- Blacklist по именам ключей покрывает `password`, `master_password`, `encryption_key`, `token` и др.
- Clipboard-события логируют только `data_type`, `entry_id`, `timeout` — не содержимое.

## Последствия
- Тесты проверяют отсутствие plaintext в `entry_data`.
- Экспорт JSON/CSV/PDF наследует те же санитизированные данные.

## Обновление (Sprint 4 доработка)
- TOTP и пароли передаются через `SecureString` + опциональный ephemeral bus без записи в системный буфер.
- Настройки clipboard хранятся в зашифрованной таблице `settings`, не в открытом `config.json`.
