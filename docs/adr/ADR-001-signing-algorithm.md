# ADR-001: Выбор алгоритма подписания логов

## Статус
Принято

## Контекст
Журнал аудита должен обеспечивать криптографическую неотрекаемость (non-repudiation) и быструю проверку целостности при тысячах записей.

## Решение
Использовать **Ed25519** как основной алгоритм подписи; **HMAC-SHA256** — как fallback, если Ed25519 недоступен.

## Обоснование
| Критерий | Ed25519 |
|----------|---------|
| Скорость | ~70k подписей/с на CPU, верификация <1 с на 1000 записей |
| Безопасность | 128-bit security, устойчив к side-channel при корректной реализации |
| Размер ключа | 32 байта seed, 64 байта подпись — компактно для SQLite |
| Стандарт | RFC 8032, поддержка в `cryptography` |

## Последствия
- Публичный ключ хранится в `audit_signing_keys` для независимой верификации экспорта.
- При компрометации seed требуется ротация мастер-пароля (отдельный ADR-003).
