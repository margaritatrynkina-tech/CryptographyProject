# ADR-002: Структура hash chain для логов

## Статус
Принято

## Контекст
Нужно обнаруживать удаление, вставку и перестановку записей в журнале, а не только изменение одной строки.

## Решение
Каждая запись содержит:
- `previous_hash` — SHA-256 хеш JSON предыдущей записи
- `entry_hash` — SHA-256 хеш текущего `entry_data`
- Ed25519 подпись над полным `entry_data`

## Обоснование
Цепочка хешей связывает записи: изменение записи N ломает `entry_hash` записи N и `previous_hash` записи N+1. Подпись защищает от подделки без знания ключа.

## Последствия
- Genesis-запись использует `previous_hash = 0×64`.
- Верификация O(n) по выбранному диапазону; для больших логов — выборочная проверка последних 1000 записей при старте.
